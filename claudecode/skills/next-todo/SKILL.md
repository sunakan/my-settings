## 手順

### Step 1: TODO.md の読み込み

`TODO.md`（カレントディレクトリ基準）を Read で読み込む。

ファイルが存在しない場合は「TODOがありません」と返して終了する。

### Step 2: 完了済み項目の整理

「検討中」セクションの各項目（`###` 見出し単位）について、参照ファイルが存在する場合は実際のファイルを Read して現在の状態と照合する。

**SKILL.md 系の TODO の場合**: 改善提案として挙げられているフィールド（`context: fork`、`disable-model-invocation` 等）が既に SKILL.md の frontmatter に存在していれば、その項目は完了済みと判定する。

**判定が難しい場合**: スキップして次の項目へ（過剰削除しない）。

完了済みと判定した項目は TODO.md から Edit で削除する（`###` 見出しから次の `---` セパレータまでを除去）。削除した項目があれば「完了済みとして削除: <項目名>」とユーザーに通知する。

### Step 3: 次の項目の特定

整理後の「検討中」セクションの最初の項目（`###` 見出し）を次のTODOとして選ぶ。

「検討中」セクションが空または存在しない場合は「検討中のTODOがありません」と返して終了する。

### Step 4: 提示

TODO.md の項目に `REVIEW.md` などの参照ファイルへのパスが記載されている場合は、それらも Read して内容を補完してから提示する。

以下の順序でユーザーに提示する:

1. **現状**: 今どうなっているか（ファイル・設定・動作）
2. **課題 / 背景**: なぜ問題なのか、このTODOが生まれた経緯
3. **対応手段**: 選択肢がある場合は複数提示し、それぞれのトレードオフを示す
4. **対応することで得られる効果**: 修正後に何が改善されるか
5. **期待**: ユーザーにとって何が嬉しくなるか

### Step 5: 確認

提示後、対応手段が複数ある場合は「どの手段で進めますか？」、単一案の場合は「進めますか？」とユーザーに確認する。

実装はユーザーが確認してから開始すること。

### Step 6: 作業完了後の TODO.md 整理

実装が完了したら（ファイル編集・設定変更などの作業が終わったタイミングで）、取り出した TODO 項目を TODO.md の「検討中」セクションから Edit で削除し、「TODO.md から `<項目名>` を削除しました」と通知する。

削除範囲: `###` 見出しから次の `---` セパレータまで（セパレータ自体も含む）。
